# AI Strategy Portfolio — Build Pack

Prepared for Ankit Kapoor, 6 September 2026.

This pack contains four standalone business requirements documents, each with a copy-ready coding-agent prompt, implementation stages, acceptance requirements, and design guidance. The numbered Markdown and Word versions contain the same substantive requirements; use Markdown for coding agents and Word for reading or annotation.

## Files

- 01_Disrupt_This_Business_BRD: a four-round competitive AI strategy game with deterministic economics and role reversal.
- 02_The_Moat_Test_BRD: an interactive product investigation with a real prototype, reproducible evaluation, and evidence-backed business interpretation.
- 03_Priced_In_BRD: financial-statement intake, reverse valuation, operating requirements, AI economics, and thesis stress testing.
- 04_Portfolio_Website_BRD: a personal editorial website, concrete design tokens, page specifications, verified reference links, and starter copy.

## How to hand a brief to an agent

Attach the entire relevant Markdown document. Say: “Implement this BRD. Start with its copy-ready coding-agent prompt and work through its acceptance requirements. Make a working vertical slice, validate the underlying logic, then refine the design. Report implemented, deferred, and blocked items honestly.”

The prompt near the end of each BRD supplements the specification; do not provide only the prompt without the full document. Existing repository, credential, and hosting instructions still apply. Each product can be built in its own repository and linked through the portfolio configuration; there is no required shared backend.

## Suggested sequence

Start with the portfolio's homepage and one case-study shell to establish the visual direction. Build Disrupt This Business as the first complete demo. Build The Moat Test and conduct actual evaluations. Build Priced In with numerical validation before live statement ingestion. Replace concept previews and case drafts as real products and evidence become available. The website can launch with fewer live demos while honestly labeling the others.

All briefs distinguish product functionality from research Ankit must actually perform. Synthetic fixtures, draft annotations, and illustrative analyses must never become fabricated users, financial results, commercial comparisons, or personal accomplishments. Public model calls need real credential and spend controls. The portfolio itself needs no AI API.

## Design direction

Warm editorial publication: strong serif headlines, readable sans-serif body, large project features, original evidence visuals, and restrained motion. The website BRD maps each reference to a specific design task rather than asking an agent to make a generic premium-looking page.

Primary references: Pentagram's Scenario project, The Pudding, Linear's UI redesign article, Stripe's 2025 annual letter, and Datawrapper's visualization writing. URLs and usage instructions are in the website BRD. These are inspiration, not permission to copy proprietary assets.

## Owner-supplied material before a finished public portfolio

Verified contact/LinkedIn/GitHub links; a real resume if desired; optional headshot; final review of biographical copy; actual demo URLs; real research evidence and authored conclusions. Missing items should remain absent or clearly labeled during development. No addresses, credentials, or personal details should be invented.
